Система логирования
    Система логирования в Java — это механизм для записи событий,
    происходящих в приложении: от информационных сообщений до ошибок и исключений.
    Это как «чёрный ящик» для программы: он помогает понять, что именно происходило в момент сбоя, отследить поток выполнения и диагностировать проблемы в проге.
Как в общих чертах работает?
    Система логирования в Java в общих чертах работает так: приложение генерирует сообщения о событиях (старт, ошибки, бизнес‑действия и т.п.), система решает, какие из них стоит сохранить, форматирует их и отправляет в нужное место (файл, консоль, удалённый сервис и т.д.).
        Ключевые компоненты:
            Logger (логгер)—точка входа в коде, через которую пишут логи.
            Обычно создают по одному на класс: private static final Logger log = LoggerFactory.getLogger(MyClass.class);.
            Логгер не пишет сам, а передаёт событие дальше.
            Уровень логирования (level) — приоритет события.
            Типичные уровни (по возрастанию важности): TRACE, DEBUG, INFO, WARN, ERROR, FATAL. Если уровень логгера ниже порога (например, логгер настроен на INFO), сообщения DEBUG и TRACE просто отбрасываются.
            Appender (аппендер) — отвечает за доставку сообщения: пишет в файл, консоль, отправляет по сети, в базу и т.п.
            У одного логгера может быть несколько аппендеров.
            Layout / Encoder — формат сообщения: что именно попадёт в лог (время, уровень, имя класса, сообщение, стек‑трейс) и в каком виде (простой текст, JSON и т.д.).
            Конфигурация — правила, которые связывают эти части: какие уровни разрешены, куда писать, какой формат использовать. Чаще всего это XML/YAML/properties‑файл.
Как устроена система логирования в java?
    Система логирования в Java устроена по принципу разделения ответственности: код приложения только сообщает о событиях, а инфраструктура решает, что с этими событиями делать (писать, игнорировать, форматировать, куда отправлять).

    Архитектурный слой: фасад vs реализация
    Это самая важная часть устройства Java почти всегда используют фасад (абстракцию API) и отдельно реализацию (движок, который реально пишет логи).

    SLF4J (Simple Logging Facade for Java)—это фасад. В коде вы пишете только через него: logger.info(...), logger.error(...). Он ничего не пишет сам, а выбирает нужную реализацию.
    Реализация (Logback, Log4j2 и т.п.)—это тот, кто реально пишет в файл/консоль/сеть.
    В Spring Boot по умолчанию: SLF4J + Logback. Это и есть то, что «устроено» в типичном проекте.

    Как проходит одно сообщение от кода до файла
    Вызов в коде: log.info("Order created: {}", orderId);
    Внутри SLF4J проверяет уровень логгера и уровень порога. Если INFO разрешён — сообщение идёт дальше.
    Фильтрация по уровню: если порог WARN, то INFO и ниже отбрасываются сразу (дешёвая операция).
    Передача в аппендеры: сообщение отправляют всем подключённым аппендерам (консоль, файл и т.д.).
    Форматирование: encoder/layout превращает событие в строку (или JSON) по шаблону: дата, уровень, имя класса, сообщение, стек‑трейс.
    Вывод: аппендер пишет результат (в файл, консоль, сокет, HTTP‑эндпоинт и т.п.).
    На каждом этапе могут быть дополнительные фильтры (по имени логгера, по содержимому, по исключениям) и асинхронность (очередь, отдельный поток), чтобы не тормозить приложение.

В приложение добавил конфигурацию логирования в main/resources.
