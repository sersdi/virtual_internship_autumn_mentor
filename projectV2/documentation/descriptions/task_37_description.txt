Архитектура компьютерной сети TCP/IP:
    Канальный (Link Layer).
    Межсетевой (Internet Layer).
    Транспортный (Transport Layer).
    Прикладной (Application Layer).

Канальный уровень.
Отвечает за передачу данных между устройствами в одном сегменте сети (например, в домашней Wi-Fi-сети или в офисе).
Здесь биты упаковываются в кадры (фреймы), к ним добавляются физические адреса (MAC-адреса) устройств.
Уровень также контролирует ошибки (с помощью контрольных сумм) и управляет доступом к среде передачи (чтобы избежать коллизий).
Примеры протоколов: Ethernet (для проводных сетей), Wi-Fi (для беспроводных), PPP (для прямого соединения между узлами).

Межсетевой уровень.
Его задача — обеспечить передачу данных между разными сетями.
Здесь используется логическая адресация — IP-адреса.
Протокол IP формирует из данных пакеты, добавляет заголовок с адресами отправителя и получателя, а маршрутизаторы на этом уровне определяют оптимальный путь следования пакета через сеть.
Важно: сам по себе IP не гарантирует надёжную доставку — пакет может потеряться, прийти в неправильном порядке или дублироваться.
За надёжность отвечают протоколы более высокого уровня.
Также на этом уровне работают вспомогательные протоколы: ICMP (для диагностики и сообщений об ошибках), ARP (для сопоставления IP-адреса с MAC-адресом).

Транспортный уровень.
Обеспечивает сквозную передачу данных между конкретными приложениями на разных устройствах.
Его ключевая задача — гарантировать целостность и правильный порядок данных.
Здесь работают протоколы TCP (Transmission Control Protocol) и UDP (User Datagram Protocol).
TCP устанавливает соединение, следит, чтобы все пакеты дошли, и при необходимости повторяет отправку потерянных.
Он идеален для задач, где важна надёжность (электронная почта, передача файлов). UDP работает быстрее, но без гарантий доставки — его выбирают для приложений, где критична низкая задержка (онлайн-игры, видеостриминг, VoIP).
Для идентификации конкретных приложений на устройстве используются порты (числовые идентификаторы).

Прикладной уровень.
Это уровень пользовательских приложений и сетевых служб. Здесь определяются протоколы для конкретных задач: HTTP/HTTPS (веб-сёрфинг), FTP (передача файлов), SMTP (отправка электронной почты), DNS (преобразование понятных имён сайтов в IP-адреса).


Протоколы в компьютерных сетях:
    На канальном уровне: PPP, IEEE 802.11 (Wi-Fi).
    На межсетевом: ICMP, IGMP (для управления multicast-потоками).
    На транспортном: SCTP (сочетает надёжность TCP и многопоточность), RTP (для передачи аудио и видео в реальном времени).
    На прикладном: SSH (безопасное удалённое подключение), SNMP (управление сетевыми устройствами), POP3/IMAP (получение почты).

Протокол TCP
Transmission Control Protocol — протокол транспортного уровня.
Он обеспечивает надёжную, упорядоченную и проверенную на ошибки передачу данных между приложениями.

Протокол IP
IP (Internet Protocol) — это протокол межсетевого уровня.
Его главная задача — обеспечить адресацию и маршрутизацию.
Каждому устройству в сети присваивается уникальный IP-адрес.
Когда данные отправляются, IP «упаковывает» их в пакеты, добавляет заголовок с адресами отправителя и получателя, а затем маршрутизаторы используют этот заголовок, чтобы определить путь следования пакета через сеть.
IP сам по себе не гарантирует, что пакет дойдёт до адресата без проблем.
Если нужна гарантия доставки, эту задачу берут на себя протоколы транспортного уровня (например, TCP).

Существуют разные версии IP. Наиболее распространены IPv4 (32-битные адреса) и IPv6 (128-битные адреса — создана для решения проблемы исчерпания адресов в IPv4).

Как всё работает вместе:
    На прикладном уровне браузер формирует HTTP-запрос.
    Запрос передаётся на транспортный уровень. Если нужна надёжность, подключается TCP (устанавливает соединение, нумерует сегменты).
    На межсетевом уровне IP «упаковывает» сегменты в пакеты, добавляет IP-адреса и отправляет их в сеть. Маршрутизаторы прокладывают путь.
    На канальном уровне пакеты преобразуются в кадры, добавляются MAC-адреса, и данные передаются по физической среде (кабель, Wi-Fi).
    На обратном пути процесс идёт в обратном порядке: каждый уровень «снимает» свой слой обработки, пока данные не дойдут до приложения.
