    Библиотека Lombok - это библиотека для языка программирования Java, которая помогает сократить объём шаблонного (boilerplate) кода за счёт автоматической генерации вспомогательных методов и конструкторов во время компиляции.
Вместо того чтобы вручную писать повторяющиеся фрагменты, разработчик добавляет в код специальные аннотации, а Lombok сам генерирует нужный код.
Основные цели использования Lombok:
    -Сокращение объёма кода. Устраняется необходимость вручную писать геттеры, сеттеры, конструкторы, методы toString(), equals() и hashCode().
    -Повышение производительности. Автоматизация рутинных задач экономит время разработчиков, позволяя сосредоточиться на бизнес-логике.
    -Снижение вероятности ошибок. Автоматическое создание кода минимизирует опечатки и другие ошибки, характерные для ручного написания.
    -Улучшение читаемости. Код становится более лаконичным и понятным, что упрощает его поддержку.

    Lombok интегрируется в процесс сборки проекта (через инструменты вроде Maven или Gradle) и работает как процессор аннотаций (annotation processor).
На этапе компиляции он анализирует аннотации в исходном коде и генерирует необходимый байт-код, который встраивается в итоговые .class-файлы.
При этом во время выполнения приложения Lombok не добавляет накладных расходов, так как всё генерируется на этапе компиляции.

    Примеры использования аннотаций
Вот некоторые из наиболее часто используемых аннотаций Lombok и их назначение:
@Getter / @Setter	Автоматически генерирует методы доступа (геттеры и сеттеры) для полей класса.
@NoArgsConstructor	Генерирует конструктор без аргументов.
@AllArgsConstructor	Создаёт конструктор, принимающий по одному аргументу для каждого поля класса.
@ToString	        Переопределяет метод toString(), формируя строку из имени класса и значений всех полей.
@EqualsAndHashCode	Автоматически генерирует реализации методов equals() и hashCode().
@Data	            Комбинация @Getter, @Setter, @ToString, @EqualsAndHashCode и @RequiredArgsConstructor. Удобна для простых классов-моделей (DTO).
@Builder	        Реализует шаблон Builder для создания объектов, что делает код более читаемым и выразительным, особенно при работе со сложными конструкторами.
@RequiredArgsConstructor	Генерирует конструктор для всех final полей и полей, помеченных как @NonNull.
@FieldDefaults	    Позволяет задать значения по умолчанию для модификаторов доступа (private, protected, public) и сделать поля final.
@Slf4j	            Автоматически создаёт экземпляр логгера (например, Logger) для класса.
@Value	            Создаёт класс сгенерированных методов для создания неизменяемого «кортежа» из полей.
@Cleanup	        Упрощает работу с ресурсами (AutoCloseable), автоматически закрывая их в конце блока.

    Важные нюансы и ограничения
Несмотря на преимущества, у Lombok есть и подводные камни, о которых стоит знать:
    -Сложность отладки. Сгенерированный код может быть менее понятен, чем ручной, что иногда затрудняет отладку.
    -Проблемы совместимости. Некоторые инструменты и фреймворки могут не поддерживать Lombok или требовать дополнительной настройки.
    -Риск неожиданного поведения. Например, использование @Data или @EqualsAndHashCode с JPA-сущностями может привести к некорректной работе hashCode() из-за мутабельности сущностей и сгенерированных ID.
    -Зависимость от библиотеки. Использование Lombok добавляет в проект зависимость от этой библиотеки, что может усложнить миграцию на другие инструменты.

    Когда стоит использовать Lombok?
    -При разработке REST API и DTO.
    -В конфигурационных классах.
    -При быстром прототипировании.
    -В микросервисной архитектуре для уменьшения объёма кода.

    Вывод
Lombok — мощный инструмент для повышения производительности и чистоты кода в Java-проектах.
Однако его стоит применять осознанно, учитывая специфику задачи и возможные риски.
Начинать можно с простых аннотаций вроде @Data или @Slf4j, а к более продвинутым возможностям переходить по мере необходимости.
