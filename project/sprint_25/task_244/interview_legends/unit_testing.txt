Пример **легенды для интервью Java Backend разработчика**,
в которой подробно и понятно описано, **как он использует юнит
и интеграционные тесты в своей работе**, и **зачем они нужны**:

🔹 **Контекст проекта**
Я участвовал в разработке backend-сервиса для финансовой платформы, где стабильность и корректность расчётов играли ключевую роль. Мы активно использовали **Spring Boot**, **PostgreSQL**, **gRPC**, и придерживались строгих требований к качеству кода. Одним из важнейших инструментов, с которыми я работал ежедневно, были **автоматические тесты**.

🔹 **Зачем я пишу тесты**
Моя цель — **не просто чтобы “покрыть” код**, а чтобы:

* Гарантировать корректность бизнес-логики даже при сложных условиях.
* Упростить рефакторинг и развитие системы без страха “сломать что-то”.
* Быстро ловить регрессии и ошибки ещё до продакшена.
* Повысить доверие команды к коду и сделать разработку устойчивой.

---

### ✅ **Юнит-тесты**

Использую юнит-тесты для **проверки бизнес-логики в изоляции**. Примеры:

* Тестировал расчёт премии (`PremiumCalculator`) с разными наборами данных.
* Проверял корректность валидации входных данных, логики переходов статусов, правил андеррайтинга.

Инструменты:

* `JUnit 5` + `Mockito` + `AssertJ`
* Использую `@Mock` и `@InjectMocks`, либо просто `new` + моки руками
* Для сложных структур — `ParameterizedTest` или `TestFactory`

Пример:

```java
@Test
void shouldApplyDiscountForLoyalCustomer() {
    var premium = calculator.calculate(basePrice, loyalCustomer);
    assertThat(premium).isEqualTo(new BigDecimal("850.00"));
}
```

---

### ✅ **Интеграционные тесты**

Использую для **проверки взаимодействия между компонентами**:

* Проверка работы `REST/gRPC контроллеров` с сервисами и БД.
* Проверка конфигурации, транзакционности, репозиториев, сериализации и всего пути запроса.

Инструменты:

* `@SpringBootTest` + `Testcontainers` + `@Transactional`
* Использую `MockMvc` для REST и `InProcessServer` для gRPC

Пример:

```java
@Test
void shouldCreatePolicyInDatabase() {
    mockMvc.perform(post("/policies")
            .contentType(MediaType.APPLICATION_JSON)
            .content(json))
        .andExpect(status().isCreated());

    assertThat(policyRepository.findAll()).hasSize(1);
}
```

---

### ✅ **Как тесты помогают в реальной работе**

* **Находить ошибки на ранних этапах**: перед коммитом я всегда запускаю локально юнит- и интеграционные тесты.
* **Работать спокойно в команде**: тесты — это страховка при командной разработке. Если кто-то меняет компонент, сразу видно, что “сломалось”.
* **Рефакторить без страха**: при изменении бизнес-логики я сначала запускаю существующие тесты, убеждаюсь что всё зелёное — и только потом начинаю менять код.
* **Документировать поведение**: хорошо написанные тесты показывают, как должен вести себя метод или модуль в разных ситуациях.
