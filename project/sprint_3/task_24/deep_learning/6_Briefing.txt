Definition of Inversion of Control (IoC):
The source explicitly states the primary task is to
"understand the Inversion of Control (IoC) design pattern."
While not providing a direct definition, it immediately
follows by outlining how IoC supports dependency acquisition,
implying that IoC is about the control over dependency
creation and management being inverted from the dependent
class to an external entity.

Three Methods for Obtaining External
Dependencies (Dependency Injection):
The core practical takeaway is that IoC, specifically
through Dependency Injection, offers three distinct ways
for a class to receive its external dependencies:

Through the constructor:
Dependencies are passed as arguments to the class's
constructor when an object is instantiated.

Through a set method:
Dependencies are set on the object after its creation
via dedicated setter methods.

Through an object property (Field Injection):
Dependencies are directly injected into public or
protected fields of the object.

The source states:
"IoC в действительности поддерживает три способа получения
внешних зависимостей классом:
- через конструктор;
- через set метод;
- через свойство объекта."
(IoC actually supports three ways for a class to receive
external dependencies:
- via constructor;
- via set method;
- via object property.)
