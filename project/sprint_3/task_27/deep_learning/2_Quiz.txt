Quiz

1. What is the primary purpose of using Lombok's
   @RequiredArgsConstructor annotation?

2. Explain the significance of specifying AccessLevel.PACKAGE
   with @RequiredArgsConstructor.

3. Why is it important for a class property to be
   declared as final for @RequiredArgsConstructor to
   include it in the generated constructor?

4. Where would you expect to find the Lombok-generated code
   if you are building your project with IntelliJ IDEA?

5. Where would you expect to find the Lombok-generated code
   if you are building your project with Gradle?

6. Briefly describe one common criticism of "Field Injection"
   as discussed in "Why field injection is evil.pdf".

7. How does Lombok help in reducing boilerplate code in Java projects?

8. If TravelCalculatePremiumServiceImpl has a non-final field,
   will @RequiredArgsConstructor include it in the generated
   constructor? Explain why or why not.

9. Why is it recommended to inspect the out/production/classes
   or build/classes folder after building a project with Lombok?

10. In the context of dependency injection, what does
    "hidden dependencies" refer to when discussing field injection?


Quiz Answer Key

1. The primary purpose of @RequiredArgsConstructor is
   to automatically generate a constructor that includes
   arguments for all final fields within a class that have
   not been initialized. This reduces the need for manually
   writing common constructor boilerplate.

2. Specifying AccessLevel.PACKAGE with @RequiredArgsConstructor
   ensures that the generated constructor is only accessible
   by other classes within the same package. This can enforce
   encapsulation and control how objects are instantiated.

3. For @RequiredArgsConstructor to include a class property
   as a constructor parameter, the property must be declared
   as final. This is because final fields are typically initialized
   once, often through a constructor, and Lombok specifically
   targets these for its generated constructors.

4. If you are building your project with IntelliJ IDEA,
   you would expect to find the Lombok-generated code
   (specifically the compiled .class files) in the
   out/production/classes folder.

5. If you are building your project with Gradle, you would
   expect to find the Lombok-generated code (the compiled
   .class files) in the build/classes folder.

6. One common criticism of field injection is reduced testability.
   Since dependencies are injected directly into fields, it
   becomes difficult to instantiate and test a class in
   isolation without a full dependency injection framework,
   leading to tightly coupled tests.

7. Lombok helps reduce boilerplate code by automating the
   generation of common code constructs like constructors,
   getters, setters, and equals/hashCode methods. This allows
   developers to write less repetitive code and focus on core
   business logic.

8. No, if TravelCalculatePremiumServiceImpl has a non-final
   field, @RequiredArgsConstructor will not include it in
   the generated constructor. The annotation specifically
   targets final fields to be included as parameters in
   the constructor it creates.

9. It is recommended to inspect the out/production/classes
   or build/classes folder to see the actual Java bytecode
   generated by Lombok. This allows developers to verify
   that Lombok has correctly added the desired constructor
   (or other code) to their class, aiding in understanding
   and debugging.

10. In the context of dependency injection, "hidden dependencies"
    refers to the situation where a class's required dependencies
    are not immediately obvious from its constructor or method
    signatures, as is often the case with field injection.
    This can make the class's requirements unclear at a glance.
