Lombok's @RequiredArgsConstructor: Principles and Practice

What is the primary purpose of the @RequiredArgsConstructor
annotation in Lombok?

The @RequiredArgsConstructor annotation in Lombok is
used to automatically generate a constructor for a class.
Specifically, it creates a constructor that includes arguments
for all final fields and any fields annotated with @NonNull.

How is the access level of the generated constructor
controlled when using @RequiredArgsConstructor?

The access level of the generated constructor is controlled
by the access parameter within the @RequiredArgsConstructor
annotation. For instance,
@RequiredArgsConstructor(access = AccessLevel.PACKAGE)
will generate a constructor with package-private access,
meaning it can only be accessed by other classes within
the same package.

What is the significance of marking a class property
as final when using @RequiredArgsConstructor?

When using @RequiredArgsConstructor, if a class property
is declared as final, Lombok will include this property
as a parameter in the generated constructor. This ensures
that the final field is initialized at the time of object
creation, adhering to Java's rules for final fields.

Where can one find the code generated by Lombok after
building a project?

After building a project, the code generated by Lombok
can be found in specific output directories. If building
with IDEA, the generated code is typically located in
out/production/classes. If building with Gradle, it can
be found in build/classes. Inspecting these folders allows
developers to see the constructors Lombok has added to their classes.

What is the main argument against field injection, according
to Oliver Drotbohm?

While the provided text doesn't explicitly detail Drotbohm's

practice of field injection. In the context of constructor
generation and the need for final fields, it implies a
preference for constructor-based dependency injection,
which allows dependencies to be clearly defined and
initialized when an object is created, promoting immutability

In the given context, how does Lombok facilitate dependency
injection, particularly when avoiding field injection?

Lombok, through annotations like @RequiredArgsConstructor,
facilitates constructor-based dependency injection.
By automatically generating constructors that take final
class properties as parameters, it encourages developers
to inject dependencies through the constructor rather than
directly into fields. This approach aligns with the principle
of "Why field injection is evil," promoting more robust and
testable code by ensuring dependencies are available at object
instantiation.

What are the benefits of using Lombok for constructor
generation in large projects?

In large projects, Lombok significantly reduces boilerplate
code by automating constructor generation. This improves code
readability, reduces the chance of manual errors, and makes
refactoring easier. For example, when new final fields are added,
Lombok automatically updates the constructor without requiring
manual modification, saving time and ensuring consistency.

How does the concept of package-private access relate to the
use of @RequiredArgsConstructor in the examples provided?

In the examples of TravelCalculatePremiumServiceImpl and
TravelCalculatePremiumController, specifying
access = AccessLevel.PACKAGE for @RequiredArgsConstructor
means that the generated constructors will only be accessible
by other classes within the same package. This can be a deliberate
design choice to restrict how these service and controller
classes are instantiated, ensuring they are primarily created
and managed by other components within their designated module
or package structure.
