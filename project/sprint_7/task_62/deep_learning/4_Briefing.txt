Briefing Document: Logging System - Object to JSON Transformation

This document outlines the core requirements and expected
outcomes for a logging system tasked with transforming Java
objects into JSON strings for persistent storage and error diagnosis.

Main Themes:

Purpose of Logging:
The primary goal of the logging system is to record information
that can later illuminate system activities, aiding in the
identification and resolution of errors. As stated in the source:
"Система логирования предназначена для сохранения любой информации,
которая в будущем может пролить свет на то, что делала система
и помочь выявить и устранить ошибки." (The logging system is
designed to save any information that in the future can shed
light on what the system was doing and help identify and
eliminate errors.)

Object to JSON Transformation:
A key functional requirement is the conversion of a specific
Java object, TravelCalculatePremiumRequest, into a JSON formatted
string. This transformation is crucial for standardized, readable,
and machine-parsable logging.

Logging Mechanism:
The transformed JSON string must then be logged into the system.
The example output indicates a standard logging framework
(e.g., Log4j or SLF4J) is expected, showing a timestamp,
thread information, log level (INFO), logger name, and the
"REQUEST:" prefix followed by the JSON string.

Developer Task & Resource Utilization:
The task explicitly instructs the developer to find an existing
solution for object-to-JSON conversion online and to validate
it with tests. This implies a preference for leveraging existing
libraries (e.g., Jackson, Gson) rather than implementing a custom
serialization mechanism. The instruction is: "PS: воспользуйтесь
интернетом, найдите решение предназначенное для преобразования
объекта в JSON, проверьте его при помощи теста." (PS: use the
internet, find a solution designed for converting an object to JSON,
test it using a test.)

Key Takeaways:

The central objective is to implement robust and informative
