What are the two main Gradle configuration
files found at the root of a project?

The two main Gradle configuration files located
at the root of a project are build.gradle and settings.gradle.
These files are crucial for defining the project's structure
and build process.

How are modules handled in a multi-module Gradle project,
and which file manages them?

In a multi-module Gradle project, there are several
separate modules. All of these modules are listed and
managed within the settings.gradle file. When the overall
build process (the build command) is executed, Gradle modules
are built independently of each other, unless there are explicit
dependencies between them.

What is the purpose of the build.gradle file located
at the root of the project?

The build.gradle file at the project's root contains
the common configuration that applies to all modules
within the project. This includes global settings such
as dependency repositories, applied plugins, and Java
compatibility versions.

What does the buildscript block and mavenCentral()
repository configuration signify?

The buildscript block, specifically the repositories
{ mavenCentral() } configuration, indicates that the
project will retrieve its dependencies from the Maven
Central repository. Maven Central is an open repository
where Java libraries are published, allowing projects to
easily access and incorporate them.

What is the function of Gradle plugins like 'java'
and 'idea' as applied in the build.gradle file?

The lines apply plugin: 'java' and apply plugin:
'idea' in the build.gradle file mean that the project
is utilizing the Gradle 'java' and 'idea' plugins.
Gradle plugins extend Gradle's capabilities, with the
'java' plugin providing functionalities for building
Java applications and the 'idea' plugin offering integration
with IntelliJ IDEA.

What do sourceCompatibility and targetCompatibility
specify in the build.gradle file?

sourceCompatibility = '21' and targetCompatibility = '21'
indicate that the project's code is written and compiled
using JDK 21. sourceCompatibility defines the Java language
version for the source code, while targetCompatibility specifies
the Java version of the generated bytecode.

Why is options.encoding = "UTF-8" used in the compileJava
and compileTestJava tasks?

The setting options.encoding = "UTF-8" within the compileJava
and compileTestJava tasks ensures that the project's source code,
both main and test files, is compiled using the UTF-8 character
encoding. This helps prevent issues with character representation
and ensures consistent compilation across different systems.

What testing framework is specified for use in the project?

The test { useJUnitPlatform() } configuration within the
build.gradle file indicates that the project utilizes JUnit 5
as its testing platform. JUnit 5 is a popular testing framework
for Java applications, providing a robust set of tools for writing
and running tests.
