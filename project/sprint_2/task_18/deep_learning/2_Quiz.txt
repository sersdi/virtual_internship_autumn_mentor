Answer Key

1. The primary critique is that the code is written in a
   purely technical language, has little connection to
   business logic, and requires understanding specific
   technical details to comprehend, making it difficult
   to maintain and understand.

2. This statement implies that the code's implementation
   focuses on technical mechanics rather than clearly
   expressing the business intent or domain concept it represents,
   making it less intuitive for non-technical stakeholders or
   even other developers to grasp its purpose.

3. Finding such code would be difficult because its technical
   nature obscures its business purpose, meaning developers
   would need to spend more time deciphering technical details
   rather than quickly identifying its role within the larger
   application.

4. Understanding these technical details is problematic
   because it adds an unnecessary cognitive load. Developers
   should ideally be able to understand the code's purpose
   from its structure and naming, without needing to recall
   specific API behaviors for simple operations.

5. The recommended approach is to extract the code responsible
   for calculating the number of days between dates into a
   separate method, giving that method a clear and descriptive
   name that explains its function.

6. The name of a newly extracted method should be so clear that,
   upon reading it, it is immediately obvious what the method does,
   without needing to inspect its internal implementation.

7. By extracting the code into a separate, well-named method,
   the original calculatePremium() method becomes more abstract
   and business-focused. Developers no longer need to immediately
   understand the technical intricacies of date conversion when
   reading the higher-level method.

8. The benefit of breaking code into small pieces is to create
   methods that perform small, complete actions. This reduces
   complexity, improves readability, and makes the code easier
   to understand, test, and reuse.

9. The main goal when identifying "pieces" of code to be
   extracted is to find segments that perform a "small,
   but complete action," allowing them to be encapsulated
   within their own methods.

10. "Business language" in code refers to using names and
    structures that directly reflect the domain concepts
    and operations, making the code's purpose clear from
    a business perspective. "Technical language," conversely,
    focuses on the specific implementation details and technical
    mechanisms, often obscuring the underlying business logic.
